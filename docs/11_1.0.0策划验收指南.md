# 1.0.0 策划验收指南

本版本提供十二章可推进与回访的主线、126 个房间、17 人名册、12 个主线首领、8 个隐藏精英、技能、物品装备与结局闭环。交付用途为策划验收；版本号不代表已经通过商业上线质量检验。

## 交付与保存

程序：`E:\Godot\release\灰烬齿轮-裂界之心-1.0.0\AshenGears.exe`。

同目录的 PCK 必须保留。普通启动为 Forward+；低配置入口 `AshenGears-LowSpec.cmd` 使用 OpenGL。验收记录、截图、SHA256 清单及本指南随包提供。旧版目录不覆盖。测试人员可复制原存档作备份，再从主菜单“新游戏”体验新档；“继续游戏”兼容旧版 0.4 / 0.6 进度。

原文件与 `.git` 保留。新增系统继续使用 schema 1，在旧档缺失新字段时建立默认背包、人物武器与技能状态；原同伴、房间索引、奖励和 Boss 旗标不变。主存档无法解析或关键字段损坏时尝试 `.backup`。结局存档回到 R12-06 终战前安全点，保留已完成结局。

## 技能、物品与战斗

T 打开招式工坊。每人战斗 C1–C3、身法 M1–M3、共鸣 T1–T3，各 3 级；前置、点数、齿芯和章节条件在右侧显示。17 人共 153 个命名节点。基本 C1 / C2 产生职业效果，C3 为高阶范围攻击；身法包含生命耐力被动、空冲和防护；共鸣使用共享 100 资源与 12 秒形态。终式消耗剩余形态时间。技能名称取原策划，实际机制以当前界面说明为准，部分原案动作组合用通用高阶、被动或共鸣效果实现，等待策划决定后续差异化。

I 背包，O 装备。物品有数量、分类、品质、详情和可用动作；武器、护甲、两个饰品、铭文按人物分配，护套全队共用。装备页可以选择已招募候补人物，选择槽位进入相应背包类别；同一件饰品不能跨槽或跨人重复占用，拥有两件才可各装备一件。消耗品作用于当前出战角色 / 共用魔力与热负荷，按钮注明目标。候补人物的专属武器无法装备给其他职业。商店与制作必须在安全休息灯附近，不能出售证物。

六个配方包含铆钉护甲、炉卫甲、东渡剑名纹、熔界护套、封界鳞甲和星烬共鸣核，缺材料时整笔拒绝。第一击败奖励和委托提供材料。每四个首次击败记录奖励一技能点。

动作验收重点：短跳 / 长跳、二段跳、预落地输入与土狼时间、冲跑、翻滚、弹反、钩索、下砸、空冲、爬梯和切人不刷新空中次数；攻击前摇不允许翻滚取消，收招允许有限取消，受击清理旧连招 / 弹道待发事件。顿帧只冻结攻击者与受击者，其他角色和弹道继续运动。新敌人有骨骼行走 / 攻击 / 受击，首领带预警、半血强化和破势窗口。

## 地图与委托

M 显示实际房间矩形与连接关系；世界、区域选项切换视图。WASD / 摇杆平移、中键拖动、滚轮以鼠标为中心缩放、R 定位当前房间、右键已探索房间增加 / 删除标记。探索度、当前位置、休息灯、传送、商人、未击败首领、未领取宝箱与能力门为主要标识。只探索过的房间显示详情，附近未探索只显示轮廓。

N 任务档案包含 12 条主线、20 条支线、8 条隐藏委托，可分页查看。当前支线使用“NPC 接取→邻室找证物→返回清理守卫→交付”的闭环，标题引用原策划，但不包含每条原案完整多幕演出。未接取时不能直接交证物，完成奖励不重复。请重点评价回访负担、任务位置提示、条件透明度与奖励价值。

## 三个结局

- **余烬黎明**：摄政击败、米菈意愿与分离核心保全，且维修所水 / 气 / 电锚点全部完成；共同分离炉心。
- **封炉长夜**：摄政击败并保全米菈意愿后可选择安全封存与撤离。
- **灰冠继承**：同条件下选择继承炉心；文本记录其道德与同伴后果。

结局采用文字演出和存档档案，未提供完整过场影片。条件不足时“共同分离”拒绝并提示回城市锚点，玩家可主动返回维修所；三结局分别记录，同一存档可以终战前继续探索。

## 设置与性能验收

主菜单 / 暂停→设置，分“氛围与画面 / 音频 / 按键”。首启动按 GPU 选择高中低，默认屏幕原生分辨率与 60 FPS；高档保留辉光、SSAO、多级阴影与较多动态灯，低档降低渲染比例和灯光预算，保留材质、场景、动作与粒子。核显低档 OpenGL 入口可作为兼容测试路线。当前实测 GPU 为 RTX 5070 Laptop，性能 JSON 不代表 1060 / 核显达标。

请在 720p / 1080p、三档、60 / 120 / 不限帧、不同音频音量组合下测试：新进入房间的卡顿、密集战斗、技能预览、连续切菜单、长时间内存趋势、原生分辨率与窗口变化、15 秒分辨率回退、按键冲突、失焦 / 恢复、音频切换与 Boss 战层。操作音、移动、战斗、物理、背景与音量设置都有程序运行验证；听感与混音仍需人工评价。

## 人工验收范围与问题模板

程序自动化主要证明路径、碰撞、输入事件、有效伤害、机关状态、掉落和存档闭环；隔离测试会清敌、补充资源或解锁部分条件，不等于从零资源完整人工通关。资源检查保证动画 / 权重存在与旧模型字节保留，不判断视觉品质。新增模型为同风格模块化原型，若按商业成品标准验收，需单独评价轮廓、动作表现、演出、音频、数值、节奏和 UI 可读性。未声称原设计全部 NPC 对话、复杂委托分支、影片、18–24 小时实测时长或联网系统已实现。

建议先分别测试新档完整主线、旧档升级、全角色收集、三个结局、支路回访与最低配置，再提交策划意见。

每个问题记录：版本 / EXE-PCK 清单、地图房间 ID、人物与装备、学习节点、进入方式、复现步骤、预期与实际、频率、画质 / 分辨率 / 帧率、截图或录屏和存档。区分阻断、体验缺陷、表现建议、数值建议；描述触发条件即可，不必预先定位代码。
